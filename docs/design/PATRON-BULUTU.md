## Bulut ayna reddi (2026-09-01) — KISMEN GEÇERSİZ

2026-09-01 "Patron modülü" notu bulut aynayı iki gerekçeyle REDDETMİŞTİ: (1) yazma gelince ya iki yönlü senkron (çatışma çözümü + kuyruk + sıralama) ya da yine canlı bağlantı gerekir; (2) atomik claim, advisory kilit ve `clientToken` idempotency'sinin tamamı tek DB varsayar. Bu plan ikisini de aşan bir model kurar, reddin kendisini değil öncülünü değiştirir:

- **Bulut hesap yapmaz, fabrika tek yazardır.** Bulut yalnız salt-okur bir özet/projeksiyon kopyası tutar; türetilmiş alanları fabrika hesaplar.
- **Yazma iki yönlü senkron DEĞİL, gelen kutusudur.** Bulutta yazılan sipariş/cari bir MESAJdır; fabrika onu çeker ve normal servis yolundan (`clientToken = mesajId` + `tokenReplay`, ya da ekleme-yalnız makbuz) yazar. Tek DB varsayımı bozulmaz; çatışma çözümü gerekmez.
- **Tünel modeli emekliye ayrılır** (B6). 2026-09-01 notunun güvenlik çekirdeği (uzaklık SOKETTEN, Access JWT fail-closed, sır hijyeni) tünel kalktığı gün konusuz kalır; o güne dek yürürlüktedir.

Arşivde 2026-09-01 notunun başına "KISMEN GEÇERSİZ → 2026-09-29" işareti kondu; not silinmez.

## Tasarım

**Kararlar (B-turları):** patronun web sürümü + Android + iOS (tek kod tabanı, tek mağaza uygulaması "TeksERP Patron") · veri: özet + raporlar + kayıt listeleri/detay + finans · tazelik: değişen kısım varsayılan 5 dk (portalda kurulum başına ayarlanır) + ekran açıkken zil ile anında · yazma: sipariş + cari (onay adımı YOK) · hesaplar bulutta bağımsız, parola + TOTP, fabrikanın bulut yöneticisi yönetir, hesap başına tek tesis · bildirimler: iş olayları + eşik + sistem sağlığı, kullanıcı başına ayrıntılı seçim/kapatma · buluttaki geçmiş portalda ayarlanır (3/13/25 ay/tümü, varsayılan 13) · eski tünel KALDIRILIR · ticari model sonra (motor ikisini taşır).

- **B1 Eşitleme sözleşmesi v1** (`Teks-Erp/src/cloud-sync/`; backend süreci içinde iş):
  - **İlke: bulut hesap yapmaz, fabrika hesaplar** (tek kaynak) — türetilmiş alanlar (açık/kapalı, bakiye, kalan metraj) fabrikadaki mevcut yardımcılarla hesaplanıp projeksiyona girer; bulut yalnız saklar/süzer/gösterir.
  - Projeksiyonlar (kolon listesi OPT-IN): özet (`boss/overview.service.ts` bölümleri — stok, sipariş, üretim, sevkiyat, fason; finans bölümü YENİ eklenir), kayıt listeleri (sipariş/satır, sevkiyat/çuval özeti, iş emri, stok özeti, cari kart + bakiye), finans (`CariService.list/statement`, `cashTransactionService.list`, `paymentService.list`, `invoiceService.list`, `ChequeService.list/summary/dueSummary`, fiyat; maliyet), defter satırları (ekleme-yalnız hareketler `createdAt`+id ile artımlı).
  - **Raporlar isteğe bağlı:** 25 rapor servisi (`services/reports/`, katalog `constants/report-catalog.ts`) her 5 dk'da hesaplanmaz; standart dönem anlık görüntüleri saatlik, özel tarih aralığı bulutta "rapor isteği" → zil `rapor` → fabrika hesaplar → saniyeler içinde bulutta. Audit raporu buluta GİTMEZ (ayak izi yerel yüzeydir).
  - Değişiklik tespiti `updatedAt` + id eşitlik bozucu filigranı (**audit'ten türetilmez**); bugün `updatedAt` indeksi yalnız Roll'da → projeksiyon tablolarına `(updatedAt, id)` indeksleri ekleyen migration (yalnız ekler). Hard delete noktaları: finansa dokunanlar (InvoiceLine, ItemPrice, taslak Invoice) AYNI tx'te ekleme-yalnız `EsitlemeSilmeDamgasi {tablo, kayitId, silindiAt}` yazar → sonraki eşitlemede anında gider (patron 24 saat hayalet satır görmez; bulut onayından + saklama süresinden sonra budanır — telemetri sınıfı); diğerleri (OrderLine, Sack, PackingGroup, PurchaseOrderLine, Batch) günlük id-kümesi özeti uzlaştırması → uyuşmazlıkta o projeksiyonun tam gönderimi. `master-data-merge` FK yeniden bağlaması ham UPDATE ile `updatedAt`'e dokunmuyor → yeni `MergeOperation` satırı görülünce etkilenen projeksiyonlar tam gönderilir; `payment-allocation` ham UPDATE'leri `updatedAt=NOW()` yazıyor ama Prisma kancasını atlıyor → bu tablolarda filigrana güvenmeden önce ölçülür. Arka plan işi `buildListWhere(req)` çağıramaz → projeksiyon sorguları kendi allowlist'leriyle, "açık" gibi koşullar mevcut tek-kaynak yardımcılardan.
  - Toplu, gzip, kurulum imzalı, idempotent paket kimliği; bulut filigranı onaylar. Yalnız `URETIM` sınıfı + `patron-bulut` hakkı gönderir (TEST/DEMO/DR göndermez; DR devralımında gönderen değişir). Aralık ve açık/kapalı kiradan (portal), yerel DB ayarı değil (dökümle taşınmasın, yerel yönetici değiştirmesin). Sözleşme sürümlü (bulut N-1'i kabul eder; eski fabrikaya "fabrika sürümü eski" bandı).
- **B2 Bulut sunucusu** (`patron/sunucu`, VDS'te ayrı konteyner + ayrı DB): çok kiracılı tek DB, her satırda `tesisId` + PostgreSQL RLS `USING (tesis_id = current_setting('app.tesis_id')::uuid)`; `SET LOCAL app.tesis_id` HER istek tx'inin ilk ifadesi (havuzlu bağlantıda sızmaz); ayarlanmamışsa `current_setting` hata → sıfır satır (fail-closed); uygulama katmanında tek yardımcı + bekçi (tesis_id'siz sorgu 0 satır); kurulum açık anahtarları `satici` iç API'sinden (iç ağ, önbellekli). Hesaplar: parola (scrypt) + TOTP, bulut izin kataloğu (okuma: özet/rapor/sipariş/sevkiyat/üretim/stok/finans-cari/kasa/çek/fiyat/maliyet; yazma: sipariş, cari; yönetim: hesaplar); ilk tesis yöneticisini satıcı portalı açar (davet bağlantısı; e-posta altyapısı v1'de yok). Saklama işi (portal ayarı), abonelik bitişinde eşitleme durur + süre sonunda imha (öncesinde dışa aktarma).
- **B3 Gelen kutusu:** bulutta `GelenKutusuKaydi {tur: SIPARIS|CARI, govde, mesajId, hesapId, durum BEKLIYOR→ISLENIYOR→ISLENDI|REDDEDILDI|IPTAL}`; zil `gelen-kutusu` → fabrika imzalı istekle çeker → **normal servis yolundan** yazar: sipariş `OrderService.create` (`order.service.ts:2034`; `prepareOrderCreate` doğrulaması; `clientToken = mesajId` + `tokenReplay`), cari `customer.service` yaratma (kod backend'de üretilir; aynı ad 409 `CUSTOMER_NAME_DUPLICATE` → REDDEDILDI). Customer'da `clientToken` YOK → idempotency fabrikadaki yeni ekleme-yalnız `BulutGelenKutusuMakbuzu {mesajId @unique, tur, varlikId, bulutHesapId, bulutHesapAdi, sonuc}` ile — varlık yaratma + makbuz AYNI tx'te (`customer.service` `createCardTx` kendi `$transaction`'ını açıyor, `:268` → tx-alan sarmalayıcı eklenir; atomik değilse idempotency yoktur), tekrar oynatma makbuzdan cevaplanır (Order/Customer'a kolon eklenmez: yeni skaler kolon = yeni yazılabilir alan tuzağı). `createdById` User FK'si → kurulum başına giriş yöntemi olmayan (parola/PIN yok) teknik kullanıcı "Patron Bulutu" (yalnız `order:write` + `customer:write`), panelde "Patron bulutunu etkinleştir" eylemiyle normal kullanıcı servisinden audit'li doğar; kimliksiz `GET /api/auth/mobile-users` ve `login-methods` listelerinden BEYANLI hariç (bekçili). İşleme sırası yerel satırda atomik claim + tek süreç (yeni advisory uzay gerekmez; gerekirse 8037, envanterle). Ret mesajı TR `details.code`. Yazar yalnız BEKLIYOR iken iptal edebilir (bulutta atomik claim).
- **B4 Uygulama** (`patron/uygulama`, Expo SDK 54 + expo-router, web dahil): Giriş (e-posta + parola → TOTP) · Pano (özet kartları + "son eşitleme") · Raporlar · Siparişler (liste/detay/yeni → gelen kutusu) · Cariler (liste/detay/bakiye/ekstre/yeni) · Sevkiyat · Üretim · Stok · Finans · Gelen kutusu durumları · Bildirim ayarları · Hesaplar (yönetici) · Profil/TOTP. Son veri çevrimdışı salt-okunur önbellek. Fabrika adı/logosu hesap tesisinden.
